# 地区基础数据初始化

## 依赖与执行

客户档案地区选择、地区路径回显依赖 `base_administrative_division`，不属于 `dating_*` 表。仅执行婚恋业务迁移不能补齐该依赖。

在目标数据库备份并完成副本验证后，通过 UTF-8 MySQL 客户端执行后端仓库的 `sql/china_administrative_division.sql`。新环境应在使用客户档案页面前完成此步骤。

该脚本自 2026-10-16 起包含：

- 缺表时建表，表及全部 10 个字段都有中文注释。
- 国家、层级、地区编码唯一索引；新表带国家、上级编码查询索引。
- 导入仓库原有 3,217 条数据：省级 34、地市级 337、区县级 2,846。
- 重复执行仅补缺失记录，不删除已有地区，不覆盖已有名称、上级编码等字段。
- 兼容原有 `uk_level_division` 索引，先建立国家维度唯一索引，再删除旧索引。

这不是行政区划更新脚本。数据沿用文件头标注的既有来源和版本，本轮未联网核对地区变更，也未扩充原数据未包含的下级地区。已有同名表但结构不同、编码跨层级重复或索引定义异常的环境，应先人工核对，不能依靠 `IF NOT EXISTS` 修复。

DDL 会自动提交；执行失败时应检查实际状态，不要直接删表重试，也不要用整库备份覆盖后续业务数据。

## 本地缺表修复工具

`scripts/Repair-LocalRegions.ps1 -PreviousDeployment <当前本地deployment.json> -Apply`

仅支持已有部署记录且当前缺少地区表的本机 `127.0.0.1:3306/ry-vue`。不传 `-Apply` 时仍会生成受保护的全库备份、创建临时副本并演练，但不修改业务库。工具依赖现有本地部署辅助脚本，不是通用生产发布工具。

工具核对运行包和数据源、备份全库、恢复临时副本、重复导入和校验，再执行本地同步。成功后删除临时副本，备份留在受访问控制保护的 `deployment-records/region-repair-*` 目录。已有地区表时会拒绝此一次性修复入口；SQL 初始化脚本本身可重复执行。

`scripts/RegionQueryProbe.java` 使用当前部署包内真实 Mapper 和服务实现，进行只读验证，不绕过 HTTP 登录、不生成登录令牌。

## 2026-10-16 验证结果

- 备份恢复后，原 52 张表的行摘要在重复初始化前后相同。
- 临时副本和本地库各通过 80 项 Mapper/服务层只读检查，包括空父编码、省市区查询、直辖市路径、三级路径、中文名称、叶子节点和未知编码。
- 全部地区无缺失父节点，全部字段注释非空。
- 重复初始化不重复插入、不覆盖副本中的自定义名称。
- 本地库同步后共 53 张表；49 张非运行日志表保持不变。操作日志、登录日志和恢复调度运行记录允许由应用独立追加，本次未停止应用。
- 后端和前端代理存活；匿名地区请求仍为 401。尚未完成登录后的浏览器页面验收，不能将只读服务层验证称为完整 HTTP 业务验收。
